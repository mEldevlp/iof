# План: Telegram-бот

Ветка `feat-telegram-bot`. Каждый этап — отдельный чат. В начале этапа прочитай этот файл и `CLAUDE.md`,
в конце отметь этап здесь как сделанный, допиши, что решили по ходу, и обнови `CLAUDE.md`.

Токен тестового бота в репозиторий, коммиты и логи не попадает. Его передают только через переменную
окружения (`IOF_TG_TOKEN` в сессии), а в бот он попадает через `iof bot token` со stdin.

## Главные решения

- **Бот — часть панели.** Модуль `web/iof_bot.py` (только stdlib), класс `Bot` работает потоком внутри `iof-web`.
  У бота и панели общая очередь `Jobs` (одна команда iof за раз) и общий `StatusCache`. Задачи бота видны
  в журнале задач панели, вид `bot`. Без панели (`install.sh --no-web`) бота нет.
- **Включается выключателем на странице**, без токена включить нельзя. Отдельного флага в `install.sh` нет:
  `iof update` запускает `install.sh` без флагов, и флаг потерялся бы при первом обновлении.
- **Long polling** (`getUpdates`, `timeout=50`), webhook не нужен: на сервере не открывается порт.
  Сетевые ошибки — повтор с нарастающей паузой до 60 с. Ответ 409 (тот же токен опрашивает кто-то ещё)
  пишется в журнал и показывается на странице.
- **Прокси нет и не будет.** Адрес Bot API задаёт `IOF_TG_API` в `web.env` (по умолчанию
  `https://api.telegram.org`), но только для стенда и CI с поддельным API.
- **Меняет только `iof`.** Настройки пишет команда `iof bot …`, секреты (токен, код приглашения) идут
  через stdin. Поток бота читает `bot.json` сам (перечитывает при смене mtime), а меняет его через `iof bot`.
  Страница вызывает `iof bot` напрямую, а не задачей `Jobs`: команды быстрые и узлы не трогают, а
  настройки не должны ждать, пока идёт `hy2 install`. Это второе исключение после терминала, его надо
  записать в `CLAUDE.md`.
- **Кому бот отвечает.** Только админам и только в личном чате (`chat.type == "private"`). Остальным молчит.
  Исключение — сообщение из 64 знаков hex (похоже на код приглашения): на него бот отвечает «код не
  подошёл». Сообщения чужих пишутся в журнал панели (ID и username), не чаще раза в минуту на один ID.
- **Повтор после перезапуска безопасен.** `offset` хранится только в памяти. При старте апдейты старше
  5 минут пропускаются. Действия выполняются только по кнопке подтверждения с одноразовым номером,
  который тоже в памяти, поэтому повторно полученный апдейт ничего не запустит.
- **Форматирование** — `parse_mode=HTML`, экранировать проще, чем MarkdownV2. Блок кода — `<pre>`:
  Telegram показывает его как блок ``` с кнопкой «копировать».
- **Перенос.** Если на сервере `migrate.conf` с `role=target`, бот не запускается: иначе два сервера
  опрашивали бы один токен. На `role=source` бот работает, но действия отказываются `migrate_guard`,
  и бот так и отвечает. После `migrate finish` на старом сервере нет `iof-web`, а на новом бот стартует сам.
  Меняющие команды `iof bot` попадают в список `migrate_guard`.

## Данные в `/root/iof`

| Путь | Формат |
|---|---|
| `bot.token` (600) | токен одной строкой |
| `bot.json` (600) | `enabled`, `username` (имя бота по `getMe`, для подсказки «напиши боту @…»), `actions` (разрешить действия), `hy2_links` (выдавать ссылки), `quiet` (`{"from": "23:00", "to": "08:00"}` или `null`), `admins`: [{`id`, `name`, `username`, `role` (`main` или `regular`), `sound` (со звуком в тихие часы), `notify` (типы уведомлений, этап 5), `added`}], `invites`: [{`hash` (sha256 от кода), `role`, `created`, `expires`}] |

`TG_TOKEN` и `TG_CHAT` в `iof.env` остаются для тех, у кого бот не включён. Если бот включён,
`tg_send` шлёт через него (этап 5). `bot.json` и `bot.token` переезжают при `iof migrate` вместе с `/root/iof`.

## Команда `iof bot`

Все меняющие подкоманды берут `flock` на `/root/iof/bot.lock`.

| Команда | Что делает |
|---|---|
| `iof bot token` | токен со stdin: проверяет `getMe`, сохраняет его и `username`. Пустой ввод — удалить токен и выключить бота |
| `iof bot on\|off` | выключатель; `on` без токена — отказ |
| `iof bot set actions\|links on\|off` | разрешить действия, выдавать ссылки Hysteria2 |
| `iof bot set quiet ЧЧ:ММ-ЧЧ:ММ\|off` | тихие часы |
| `iof bot invite main\|regular` | печатает код приглашения: sha256 от 32 случайных байт, 64 знака hex. В `bot.json` — sha256 кода, роль, срок 24 ч |
| `iof bot invite del <начало хэша>` | отозвать приглашение |
| `iof bot redeem` | вызывает поток бота: со stdin `код`, `id`, `имя`, `username`. Код верный и не просрочен — админ добавлен, приглашение удалено |
| `iof bot admin set <id> role main\|regular` | сменить роль |
| `iof bot admin set <id> sound on\|off` | со звуком в тихие часы |
| `iof bot admin del <id>` | удалить админа |
| `iof bot show` | состояние для консоли: включён ли, бот, админы, приглашения (без кодов) |

## Админы и роли

- Админ добавляется только приглашением. В панели жмёшь «Добавить админа», выбираешь роль, панель
  показывает код (64 знака hex). Код передаёшь будущему админу, он отправляет его боту — и становится
  админом. Код одноразовый, живёт 24 часа, панель показывает его один раз. На сервере хранится только хэш кода.
- Роли: **Главный** и **Обычный**. Роль выбирается при создании приглашения и меняется на странице.
- Что доступно ролям: просмотр и ссылки — обоим, действия — только главному (если не решим иначе, см. вопросы).
  Какие уведомления доступны обычному, решаем в начале этапа 5.
- Удалять админов и менять роли можно только в панели, не из бота.

## Этап 1. Каркас

- `web/iof_bot.py`: класс `Bot` (поток, `getUpdates`, разбор сообщений, отправка), клиент Bot API на urllib.
  В `iof-web.py` — запуск потока и передача ему `Jobs`, `StatusCache`, пути к `iof`. Ошибка импорта модуля
  не валит панель.
- Команды бота на этом этапе: `/start` (приветствие, для админа — что он может), `/help`, приём кода
  приглашения. `setMyCommands` при старте.
- `iof bot …` целиком, кроме того, что относится к уведомлениям. `migrate_guard`, `usage()`.
- `install.sh`: копирует `iof_bot.py`, проверяет его `ast.parse`. `ci/lint.sh`: pyflakes и разбор для `iof_bot.py`.
- Стенд: `stand/fake-tg.py` — поддельный Bot API на stdlib (`getMe`, `getUpdates`, `sendMessage`,
  `sendPhoto`, `editMessageText`, `answerCallbackQuery`, `setMyCommands`, плюс служебный вход для
  тестов: подложить апдейт и забрать отправленное). `stand.sh setup` поднимает его на old и пишет
  `IOF_TG_API` в `web.env`. `test.sh`: токен, включение, приглашение (верное, неверное, повторное,
  просроченное), чужой пользователь без ответа, групповой чат игнорируется, отказ `iof bot` при переносе.
- Живая проверка: токен из `IOF_TG_TOKEN`, `getMe`. Добавить админа на живом боте может только человек:
  бот не начинает чат первым. Поэтому код приглашения отправляет пользователь.

Сделано всё из списка выше. `stand/test.sh` проверяет бота через поддельный API (44 проверки, шаг

### Решено по ходу этапа 1

- По умолчанию `actions: false` (действия из бота включают явно), `hy2_links: true`, `quiet: null`.
  `notify` у нового админа `null` — «по умолчанию», что это значит, решаем на этапе 5.
- Код приглашения влезает в параметр `start` ссылки Telegram (до 64 знаков), поэтому `iof bot invite`
  печатает и ссылку `https://t.me/<бот>?start=<код>`: по ней Telegram сам отправит боту `/start <код>`.
  Бот принимает и код отдельным сообщением, и `/start <код>`. На странице (этап 2) можно дать ссылку и QR.
- `iof bot invite` печатает код отдельной строкой из 64 знаков hex — по ней его найдёт панель.
  Неиспользованных приглашений не больше 20. `invite del` принимает начало хэша от 6 знаков.
- `iof bot redeem` печатает `result=added|already|bad` и `role=`. Истёкшие приглашения выбрасываются
  при любой записи `bot.json`, так что истёкший код — тоже `bad`, и бот отвечает одинаково: «не подошёл:
  неверный, уже использован или истёк». Если пишет уже админ — `already`, приглашение не тратится.
  При переносе (`role=source`) `redeem` отказывает `migrate_guard`, и бот отвечает «идёт перенос».
- От одного чужого ID бот принимает не больше 5 кодов в минуту, дальше молчит: каждый код — запуск `iof`.
- `iof bot` берёт `IOF_TG_API` из окружения (его передаёт панель) или из `web.env`: `iof bot token` в консоли
  стенда тоже идёт в поддельный API. Больше ничего `iof` из `web.env` не читает.
- Состояние потока для страницы (этап 2): `srv.bot.state()` → `state` (`off`, `no_token`, `migrate`,
  `running`, `error`, `conflict`), `error` (текст для страницы), `since`, `username`, `api` (если не Telegram).
  `srv.bot` бывает `None`: модуль не загрузился, причина в журнале панели — страница должна это показать.
- Паузу после ошибки (до 60 с) прерывает смена `bot.json` или `bot.token`: новый токен подхватывается
  сразу. Выключение во время `getUpdates` с настоящим Telegram заметно только после ответа (до 50 с),
  а пришедшие за это время апдейты бот не обрабатывает и не подтверждает.
- Поддельный API (`stand/fake-tg.py`): `getUpdates` ждёт не дольше `--max-wait` (на стенде 5 с), токен с
  номером бота 0 — отозванный (401), второй опрос обрывает первый ответом 409. `sendPhoto` принимает
  multipart; клиент `Api` в боте пока умеет только JSON — multipart добавится на этапе 4.
- Идея для этапа 5: сообщать главным админам, что по приглашению добавился новый админ (утёкший код
  будет видно сразу).

## Этап 2. Страница «Телеграм бот»

- `bot.html` + `bot.js`, пункт «Телеграм бот» в разделе «Управление» во всех html, `STATIC_FILES`,
  демо-данные, цвета и классы из `design.md` (новые — туда же).
- Карточка «Бот»: выключатель, поле токена `type="password"`. Панель токен не отдаёт: если токен
  сохранён, поле пустое с подсказкой «сохранён; введи новый, чтобы заменить». Состояние: работает,
  нет токена, ошибка связи, 409.
- Карточка «Настройки»: разрешить действия, ссылки Hysteria2, тихие часы (два поля времени или «выкл.»).
- Карточка «Админы»: имя, @username, ID, роль (выбор), «со звуком в тихие часы», удалить. Кнопка «Добавить
  админа» → выбор роли → диалог с кодом, кнопкой «Копировать» и подсказкой «отправь код боту @…».
  Ниже — неиспользованные приглашения (роль, когда истекает, «Отозвать»).
- API: `GET /api/bot` (`bot.json` без хэшей приглашений, `token: true|false`, состояние потока),
  `POST /api/bot` (`action`: `token`, `enable`, `set`, `invite`, `invite_del`, `admin_set`, `admin_del`),
  обычная защита POST. Токен уходит в `iof bot token` через stdin и в журнал не пишется.
- `test.sh`: `/api/bot` без токена в ответе, смена настроек и приглашение через панель.

### Итог этапа 2

Живая проверка на `new` (настоящий Telegram): тихие часы, приглашение и его отзыв, выключение и включение.

### Решено по ходу этапа 2

- `POST /api/bot` отвечает свежим состоянием страницы (`bot`), отдельный GET после действия не нужен.
  Код приглашения приходит только в ответе на `invite` и живёт только в диалоге: при закрытии он стирается.
  Страница показывает ссылку `t.me/<бот>?start=<код>` текстом с кнопкой «Копировать», без QR и без
  ссылки `<a href>`: внешних адресов в статике нет (правило CSP в `ci/lint.sh`).
- Токен удаляется только явным `{action: "token", delete: true}` (кнопка «Удалить токен» с подтверждением),
  пустое поле — ошибка формы, а не удаление.
- Панель проверяет поля строже `iof`: тихие часы только `ЧЧ:ММ` с двумя цифрами (так их даёт `<input type="time">`).
- В журнал панели — только команда (`бот: из панели iof bot set actions on`), без токена и кода.
- Поток бота замечает выключение только после ответа на текущий `getUpdates` (с Telegram — до 50 с),
  поэтому страница показывает «Выключается…» и опрашивает `api/bot` раз в 2 с. Включение раньше тоже
  ждало ответа на опрос: `Bot.cycle` теперь ставит `running` сразу, если токен уже проверен и бот был
  выключен (после ошибки — по-прежнему только когда опрос пройдёт).
- В `/api/bot` есть `tz` (смещение времени сервера): тихие часы задаются по времени сервера, страница это пишет.
- Последнего главного админа можно разжаловать или удалить, но страница сначала спрашивает подтверждение
  и показывает плашку «главных админов нет».

## Этап 3. Команды просмотра

- `/status`: сколько узлов в норме и с проблемами, кнопки по узлам. `/node <имя>` или кнопка — как страница
  узла: адрес, нагрузка, службы, проблемы. `/audit`: итог последней проверки по блокам и проблемные
  проверки. `/service`: версия, есть ли обновления, последнее ночное обслуживание. `/hy2`: группы
  (ссылки — этап 4).
- Данные берутся тем же кодом, что и для страниц: `StatusCache`, `read_*`, `iof api audit|service`.
- Кнопки inline, `callback_data` не длиннее 64 байт. Длинный ответ режется по 4096 знаков.
- `test.sh`: ответы на каждую команду через поддельный API.

## Этап 4. Действия и ссылки

- Действия (если `actions` включён и роль позволяет): `/check`, перезапуск Hysteria2 на узле,
  проверка узла (`audit run server|dpi`), `hy2 add <подпись> [--hop]`, `hy2 del`, `hy2 refresh`.
  Удаление узлов, перенос, `iof update`, блок-лист и смена портов — только в панели.
- Каждое действие — кнопка «Подтвердить» с одноразовым номером (в памяти, 5 минут). Задача идёт в `Jobs`,
  вид `bot`; если очередь занята — ответ, чем именно. Ход задачи — одно сообщение, `editMessageText`
  раз в 3 с: шаг, последние строки, итог (ok, warn, fail).
- Ссылки Hysteria2 (если `hy2_links` включено): `/hy2` → группа кнопкой → на каждую ссылку одно
  сообщение: фото QR (`sendPhoto`, PNG из `qrencode -t PNG`) и подпись — узел и ссылка в `<pre>`.
  Без `qrencode` — только текст. Сообщения не удаляются. Ссылки не пишутся в журнал панели и задач.
- `test.sh`: подтверждение, устаревшая кнопка, отказ без прав и при переносе, создание и удаление группы,
  ссылки с QR.

## Этап 5. Уведомления

- В начале этапа решаем: список типов уведомлений и какие из них доступны обычному админу.
  Кандидаты: проблемы и восстановление узлов (`iof check`), ухудшение аудита, итог ночного обслуживания,
  итог проверки с ПК, вышли обновления iof.
- Каждому админу свой набор (`notify`), галочки на странице. Главному доступны все типы.
- Тихие часы общие. В тихие часы сообщения уходят с `disable_notification`, кроме админов с `sound`.
- `tg_send <тип> <текст>` в `iof.sh`: если бот включён — по `bot.json` каждому подписанному админу,
  иначе как сейчас (`TG_TOKEN`, `TG_CHAT`).
- README (раздел про бота), скриншот `docs/panel-bot.png` в тёмной теме, `CLAUDE.md` целиком, итоговый
  прогон на стенде и в CI, живой бот.

## Вопросы

1. Действия из бота — только главному админу? По умолчанию да.
2. Код приглашения живёт 24 часа и одноразовый. По умолчанию так.
3. Ссылки Hysteria2 доступны обоим ролям, выключатель `hy2_links` по умолчанию включён. По умолчанию так.
4. Уведомления для обычного админа — решаем в начале этапа 5.
