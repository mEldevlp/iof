# План: страница «Безопасность»

Это план из первого шага задачи «страница "Безопасность" в iof-web» (изучить код, показать план, ждать подтверждения). Код я только читал, ничего не менял. Ниже план по пунктам и в конце 8 вопросов. По каждому вопросу есть вариант по умолчанию: если не возразишь, сделаю так.

## Главные решения

- **Узлы только собирают факты.** `n_audit_*` на bash печатают `ключ=значение`, как `n_status`. Секретов в выводе нет: пароль Salamander и параметры AWG заменяются коротким хэшем с солью запуска. Соль не сохраняется, поэтому хэши годятся только для сравнения внутри одной проверки.
- **Оценка на управляющем сервере, в `iof.sh`.** Статус, значение, «как исправить» с настоящими портами и «почему важно» формируются в одном месте. Их одинаково видят консоль, Telegram и панель.
- **Для JSON нужен python3 на управляющем сервере.** Без него `iof audit` завершится с подсказкой `apt install python3`. Узлам python3 нужен только для мишеней этапа 3.
- **`audit run` при переносе разрешён**, как `check`: узлы он не меняет. Мишени и будущие действия идут под `migrate_guard`.

## Команды и функции

| Команда | Что делает |
|---|---|
| `iof [-n узлы] audit run [server\|dpi\|all]` | опрос через `pmap`, таблица в консоль, результат в `/root/iof/audit` |
| `iof audit show [узел]` | последняя проверка без опроса, с «как исправить» |
| `iof audit cron` | для cron раз в сутки: `run all`, запись в историю, Telegram при ухудшении |
| `iof api audit` | JSON последней проверки, без опроса |
| `iof audit probe start\|stop\|import\|list` | этап 3: мишени, приём результата (JSON через stdin), история |

- **На узлах:** `n_audit_server` (блок 1), `n_audit_dpi` (блок 2), `n_audit_listen` (общий разбор `ss`), на этапе 3 `n_probe_start` и `n_probe_stop`. Все попадают в `NODE_FUNCS`.
- **На управляющем сервере:** `audit_job`, `audit_eval_server`, `audit_eval_dpi`, `audit_catalog`, `audit_save`, `audit_diff`, `cmd_audit`, `api_audit`.
- **Проверки снаружи узла** (80/443, сертификат, ping, PTR, QUIC, whois, реестр) идут с управляющего сервера в том же задании `pmap`.
- **Таймауты:** каждая внешняя команда под `timeout`, весь опрос узла ограничен 120 с. Недоступный узел получает `reachable: false`, все его проверки показываются как `none` «нет связи».

## Файлы в `/root/iof`

| Путь | Формат |
|---|---|
| `audit/server.json`, `audit/dpi.json` | последняя проверка блока. Проверка одного узла заменяет только его запись, у каждого узла своё время |
| `audit/history.jsonl` | строка на запуск: время, блок, счётчики статусов, что ухудшилось. Хранится `AUDIT_KEEP` последних |
| `audit/cache/` | скачанные списки (сканеры, реестр) и ответы whois, обновляются не чаще раза в сутки |
| `audit/probe/session.json` | текущая сессия проверки с ПК: мишени, порты, отпечаток сертификата, контроль с управляющего сервера |
| `audit/probe/<время>.json` | результаты проверок с ПК с меткой сети, последние `AUDIT_KEEP` |
| `probe-white.txt`, `probe-black.txt` | контрольные списки, создаются со значениями по умолчанию |

## Блок 1: проверки

| Проверка | good | warn | crit |
|---|---|---|---|
| root по SSH | `no`, `prohibit-password` | `yes`, пароли выключены | `yes` и пароли включены |
| Вход по паролю | выключен | включён, root по паролю нельзя | включён вместе с root |
| Порт SSH | любой при входе только по ключу | 22 при включённых паролях | нет |
| Вход по ключу | включён, права `authorized_keys` в порядке | права шире 600 | нет |
| Файрвол | входящие по умолчанию запрещены | политика ACCEPT или файрвола нет | нет файрвола и есть лишние порты |
| fail2ban или CrowdSec | работает | нет, пароли выключены | нет, пароли включены |
| Порт sshd-jail | совпадает с портом SSH | не совпадает | нет |
| Неудачные входы за 24 ч | пароли выключены или меньше 10 | 10–50 | больше 50 при включённых паролях |
| Обновления | нет | есть | есть обновления безопасности, nightly не работал 7+ дней |
| Перезагрузка | не нужна | нужна | нет |
| iof-nightly на узле | отработал за 48 ч | давно или никогда | нет |
| Слушающие порты | только ожидаемые | есть лишние | лишние и нет файрвола |
| Журнал sudo | journald, auth.log или свой файл | нет | выключен |
| pwquality | `minlen` от 12 | меньше или не настроено | нет |
| SUID | стандартный набор Ubuntu 24.04 | есть другие | нет |

- **Рекомендации не отрежут iof.** Для root советую `prohibit-password`, а не `no`, если iof заходит под root. При смене порта SSH команда включает правку `nodes.conf`. Команда для ufw сначала открывает SSH, Hysteria2, AWG и порты ретранслятора, потом включает запрет.
- **Свои правила.** Цепочки `IOF-*`, `DOCKER*`, `ufw-*`, `f2b-*` чужими не считаются.
- **Ожидаемые порты:** sshd, hysteria (UDP и `listenHTTP(S)`), порты контейнеров `amnezia-*`, локальные слушатели на loopback, iof-web на 127.0.0.1. Порты ретранслятора показываются отдельно (это DNAT, сокета нет) и сверяются с `relays.conf`.
- **SUID:** поиск пропускает `/var/lib/docker`, `/var/lib/containerd` и `/snap`.

## Блок 2: проверки (пункты 1–4 и 6)

| Группа | Проверки и статусы |
|---|---|
| Hysteria2 | **Режим маскировки:** Salamander задан, или без него с рабочим masquerade — good; ни того ни другого — warn. **Masquerade:** тип и жива ли цель; при Salamander — none с объяснением. **Порт:** 443 — good, другой — warn. **Port hopping:** диапазон в `listen` или правила REDIRECT/DNAT; нет — warn. **Расхождение с шаблоном:** сравнение хэшей блоков верхнего уровня без пользователей `auth`; отличается — warn со списком блоков |
| AmneziaWG | **Параметры:** как у обычного WireGuard — crit; вне допустимых диапазонов — warn. **Одинаковые на узлах:** по хэшу; одинаковые — warn (один отпечаток на всех), разные — good |
| Зондирование | **80 и 443/tcp:** что отвечает и какой сертификат; самоподписанный на чужое имя — warn. **ICMP:** отвечает — good, молчит — none. **hostname и PTR:** слова vpn, proxy, hy2, wg, awg и подобные — warn. **Баннеры лишних портов.** **iof-web только на loopback** |
| Сканеры | ipset `iof-block` и цепочка `IOF-BLOCK`, число подсетей, возраст списка. Без `BLOCKLIST_URL` — none |
| Репутация | **ASN и хостер** по whois — справка. **Адрес в реестре:** найден — crit. Без `REGISTRY_URL` — none |
| Гигиена | Срок хранения journald, уровень логов hysteria-server (при `info` адреса клиентов пишутся в журнал), размер и ограничение лога контейнера AWG, синхронизация времени |

Имена полей AWG уже есть в `n_awg_add`: `Jc`, `Jmin`, `Jmax`, `S1`–`S4`, `H1`–`H4` и закомментированные `I1`–`I5`.

## Панель: эндпоинты

| Эндпоинт | Защита | Что делает |
|---|---|---|
| `GET /api/security` | пароль, Host | `iof api audit` плюс состояние сессии зонда, `busy`, `migrate` |
| `POST /api/security` `{block, node}` | пароль, Host, CSRF | задача Jobs, kind `audit`: `iof -n <узел> audit run <блок>` |
| `POST /api/probe` `{action: start\|cancel, nodes, origin}` | пароль, Host, CSRF | сессия с билетом и короткая задача Jobs, kind `probe` |
| `GET /api/probe` | пароль, Host | состояние сессии для опроса страницей |
| `GET /api/probe/script?t=` | билет, Host | скрипт `.ps1`, `no-store`, один раз по билету |
| `POST /api/probe/result?t=` | билет, Host, `X-IOF-Request`, JSON до 256 КБ | приём отчёта, один раз по билету |

- **Билет:** `secrets.token_urlsafe`, живёт столько же, сколько мишени (`PROBE_TTL`, 15 минут). В журнале маскируется тем же `TICKET_IN_URL`. Сессия одна за раз.
- **Одноразовость:** скрипт выдаётся по билету один раз, результат принимается один раз. Повтор и чужой билет получают 403.
- **Сохранение результата:** отчёт уходит в `iof audit probe import` через stdin задачей Jobs из двух шагов (импорт, остановка мишеней). Если Jobs занят, отчёт ждёт в памяти панели и запускается по `on_done`. Ожидание пользователя — состояние сессии, а не задача.
- **Адрес панели для скрипта:** `location.origin` передаётся при создании сессии и сверяется со списком разрешённых хостов.

## Этап 3: проверка с ПК

- **Мишени (`n_probe_start`).** Юнит `iof-probe-<id>` через `systemd-run` с `RuntimeMaxSec`. Внутри python3: TLS с самоподписанным сертификатом, отдаёт 256 КБ и IP источника, плюс UDP-эхо на том же номере порта.
- **Токен и чужие запросы.** Токен лежит в файле 600 в `/run`, в аргументах его нет. На запрос без токена мишень молчит.
- **Файрвол.** Если входящие режутся, `ExecStartPre` добавляет правило ACCEPT в INPUT с комментарием, `ExecStopPost` снимает его и удаляет файлы. `IOF-*` не трогаются. Чистый nftables без iptables не поддержу: узел получит none с объяснением.
- **Контроль.** Сразу после запуска управляющий сервер сам проходит все слои до каждой мишени. Это второй сигнал для HIGH и основание для DOWN.
- **Скрипт.** Файл `web/probe.ps1`, ставится в `/opt/iof-web`. Он собирает только сырую трассу по слоям, вывод в консоль на английском. Сертификат мишени сверяется по отпечатку.
- **Вердикт считает `iof audit probe import`.** Так его можно проверить на стенде готовым JSON. crit только при HIGH.
- **Защита от VPN.** whois по IP источника, сравнение с адресами из `nodes.conf`, список адаптеров и системный прокси из отчёта.

**Как сделано (этап 3).** Отличия от плана выше:

- `PROBE_PORTS` — один порт или диапазон для всех узлов, а не «по порядку»: порядок `nodes.conf`
  с портами не связан, а управляющий сервер может и не быть узлом.
- `probe stop` не удаляет сессию, а помечает её остановленной: `import` можно сделать и после неё.
  Поэтому задача панели с отчётом сначала останавливает мишени, потом импортирует.
- Мишень отвечает на TLS-рукопожатие всем (иначе токен пришлось бы класть в SNI), но без токена
  в первой строке не шлёт ничего; UDP без токена молчит.
- Кроме UDP-эха есть UDP, похожий на QUIC v1 Initial (видно, режут ли именно QUIC), и зонд согласования
  версий на порт Hysteria2. Контрольные списки — `probe-white.txt` и `probe-black.txt` в `/root/iof`.
- Своя таблица nftables с политикой drop — мишень не поднимается (`none`), даже если iptables есть:
  его правило такой пакет не пропустит.
- `hysteria.exe` ищется в текущей папке, в PATH или по `$env:IOF_HYSTERIA`, поля на странице нет.

## Настройки

В `iof.env`: `AUDIT_KEEP=30`, `BLOCKLIST_URL=""`, `REGISTRY_URL=""`, `PROBE_TTL=900`, `PROBE_PORTS=""` (пусто — случайные 20000–60000; диапазон нужен, если у хостера свой файрвол).

В `web.env` ничего нового: панель получает всё из `iof api audit` и вывода `probe start`. Истории с `HY2_TEMPLATE` не будет.

## Этап 4

Действия по результатам проверки: iof сам меняет узлы. Всё под `migrate_guard`, из панели — только на одном узле, выбранном в диалоге.

**Решения (подтверждены).**

1. **Старая Hysteria2.** Смене портов нужна версия от 2.12.3. Диапазон в `listen` есть с 2.8.0, но до 2.12.3 правила заворачивали и исходящий UDP самого узла. Старые узлы обновляет новая команда `iof hy2 upgrade`: официальный установщик, бинарник и юнит до этого копируются и возвращаются, если служба не поднялась.
2. **Ссылки.** Выданные клиентам ссылки не меняются. Список портов (`host:443,10000-19999`) получают только группы, которым его включили (`iof hy2 add "Подпись" --hop`, кнопка «Список портов» на странице Hysteria2). Его импортируют Hiddify с 5.5.5 и официальный клиент, а v2rayN и Hiddify старше — нет. Параметр `mport` (v2rayN, 3x-ui) iof не пишет: Hiddify его не читает.
3. **Диапазон.** Многопортовость остаётся: на узле она ничего не ломает. По умолчанию `HY2_HOP=10000-19999` в `iof.env`, для одного запуска — `--ports a-b`. Диапазон ниже 20000–60000, откуда iof сам берёт порты ретрансляторов и мишеней.
4. **Блок-лист.** Источник — `BLOCKLIST_URL`. Обновляет отдельная строка cron `iof block update` (её подсказывают `install.sh` и страница). Если список не скачался, на узлах остаётся прежний.
5. **Панель.** Только по одному узлу: кнопка в проверке открывает диалог со списком узлов.

**Как сделано и чем отличается от плана выше.**

- В `listen` пишется `:443,10000-19999`, а не `:20000-50000`. Hysteria2 слушает первый порт списка: с одним диапазоном основной порт сменился бы и выданные ссылки и DNAT ретрансляторов перестали бы работать.
- Файрвол узла диапазон не открывает: REDIRECT срабатывает в `nat PREROUTING` раньше `filter INPUT`, и до ufw и политики DROP пакет доходит уже с основным портом. Проверено на стенде на узле с политикой DROP. Файрвол хостера iof не видит, об этом пишет вывод команды и проверка.
- Правила ставит сама Hysteria2: nftables, если есть `nft`, иначе iptables. Если служба с ними не поднялась (в ядре нет нужных модулей, как в WSL без fib для IPv6), iof повторяет запуск с `HYSTERIA_FIREWALL_BACKEND=iptables`. Не вышло и так — конфиг возвращается. Drop-in перед стартом убирает правила, оставшиеся после падения службы: без этого на iptables служба не запустилась бы.
- Проверка `hy2_hop` теперь находит и правила iptables Hysteria2 (цепочка `HYSTERIA-PR-*`). Раньше она видела только nftables.
- Блок-лист стоит в `raw PREROUTING`, а не в INPUT, как было в плане: через INPUT не идёт трафик к портам контейнеров Docker и ретранслятора. Частные сети, записи шире /16 и IPv6 не применяются. Не блокируются никогда: узлы из `nodes.conf`, адреса управляющего сервера, `BLOCK_ALLOW`, собеседники текущих сессий SSH на узле, его собственные адреса.
- Диалог `.dialog` — обобщение `.qr-dialog`, окно QR перешло на него.

**Ещё безопасные действия из «как исправить»** (не сделаны, ждут решения): уровень журнала Hysteria2 `warn` через drop-in, срок хранения journald, `timedatectl set-ntp true`, masquerade `proxy` там, где нет ни Salamander, ни masquerade, fail2ban с jail `sshd` на нужный порт. Не годятся для кнопки:
- выключение входа по паролю и `ufw enable` — могут отрезать администратора;
- лог контейнера AWG — нужно пересоздавать контейнер;
- перенос панели на loopback — отрежет того, кто открывает её снаружи.

   ```bash
   sudo docker exec amnezia-awg2 sed -n '/^\[Interface\]/,/^\[Peer\]/p' /opt/amnezia/awg/awg0.conf | grep -vE 'PrivateKey|Peer'
   ```

2. **HTTP/3 к masquerade.** В Ubuntu 24.04 нет клиента HTTP/3: curl собран без него, в stdlib python его нет. По умолчанию: зонд согласования версий QUIC с управляющего сервера (без зависимостей; показывает, отвечает ли порт как QUIC-сервер или молчит под Salamander) плюс проверка цели masquerade с узла. Настоящий GET делаю, только если curl на управляющем сервере умеет `--http3`.
3. **whois.** По умолчанию: свой запрос на порт 43 через IANA к RIPE, ARIN или APNIC, без пакета `whois`. У ARIN и APNIC номер AS бывает пустым. Team Cymru даёт ASN надёжнее, но ему уйдут адреса узлов и твой домашний IP. Подключать?
4. **Формат списков.** По умолчанию `BLOCKLIST_URL` и `REGISTRY_URL` — текст, по IP или CIDR в строке, `#` — комментарий. Если планируешь `dump.csv` реестра (сотни МБ), скажи: нужен отдельный разбор.
Решения по 5–7 (подтверждены): 5 — ссылки из буфера обмена с согласием на ПК; 6 — не публикация портов
в `compose.yml` (UDP через 127.0.0.1 из WSL не доходит, контейнеры пересоздались бы), а `stand.sh pc on`
с DNAT в WSL и `$env:IOF_PROBE_MAP`; 7 — без python3 `none` с командой, `stand.sh setup` ставит его только
на node1, чтобы стенд проверял оба случая.

5. **Hysteria2 по-настоящему.** Клиенту нужен пароль группы, а при Salamander ещё и его пароль. Через панель секреты идти не должны. По умолчанию: скрипт берёт ссылки `hy2://` из буфера обмена (кнопка «Скопировать» на странице Hysteria2) и спрашивает согласие. `hysteria.exe` ищет по пути из поля на странице. В отчёт идут только хост и порт. Альтернатива: проверка без пароля до ответа «authentication error», но с Salamander она не работает.
6. **Стенд и Windows.** С Windows адреса 172.30.0.x недоступны, скрипт до мишеней не дойдёт. По умолчанию: в `compose.yml` публикую по одному порту на сервер (TCP и UDP), `PROBE_PORTS` выдаёт узлам порты по порядку, а скрипт понимает `$env:IOF_PROBE_HOST` — подмену адреса для стенда. Альтернатива: маршрут в Windows до сети Docker, нужны права администратора и правка iptables в WSL.
7. **python3 на узлах.** Мишеням он нужен. На облачных образах Ubuntu он есть, на node1 и node2 стенда его нет. По умолчанию: на узле без python3 — none с командой `apt install python3`, сам ничего не ставлю; `stand.sh setup` ставит python3 на node1 и node2, `new` остаётся чистым.
8. **Telegram.** По умолчанию: ухудшение — проверка стала хуже прошлого раза (good→warn, warn→crit). Первая проверка задаёт базу без сообщения. Потеря связи с узлом ухудшением не считается: о ней сообщает `iof check`. Длинное сообщение обрезается со ссылкой на панель.
