## Обновление

На странице «Сервис» нажмите «Проверить обновления». Панель покажет обе версии:
**Стабильная** выбрана по умолчанию, **Тестовая** выбирается вручную. Тестовые выпуски
появляются после быстрой проверки сборки каждого push в master; полный CI может ещё выполняться.
Стабильным становится только явно выбранный тестовый выпуск после успешного полного CI.

Кнопка обновления устанавливает именно показанный и подтверждённый тег, даже если за это время
появится более новый выпуск или изменится master. Черновики и теги без публикации не устанавливаются.
Из терминала управляющего сервера:

```bash
sudo iof update --release
```

Тестовый канал:

```bash
sudo iof update --release --channel test
```

Конкретный опубликованный тестовый выпуск:

```bash
sudo iof update --release --channel test --tag v0.12
```

Если стабильная версия старее установленной тестовой, на «Сервисе» доступна отдельная кнопка
«Вернуться на стабильную» с предупреждением и подтверждением. Обычное обновление версию не понижает.
Эквивалент явного возврата из терминала (укажите нужный стабильный тег):

```bash
sudo iof update --release --channel stable --tag v0.9 --allow-downgrade
```

При продвижении уже установленного тестового выпуска в стабильный его тег и коммит не меняются.
После проверки обновлений панель покажет стабильный канал без переустановки.
Обычный `iof update` в рабочей ветке сохраняет обновление через `git pull --ff-only`;
на отсоединённом HEAD по умолчанию используется стабильный канал.

### Публикация выпусков

Каждый push в master после проверки сборки получает GitHub pre-release с точным коммитом push.
Номера общие для обоих каналов: `v0.9`, `v0.10`, …, без суффиксов. Быстрые push не отменяют
публикации друг друга, повтор запуска для того же коммита не создаёт новую версию.

В GitHub Actions → **CI** → **Run workflow**:

- `action: publish`, `target: <полный SHA>` — выпустить тестовую версию промежуточного коммита
  из истории master после быстрой проверки сборки;
- `action: promote`, `target: v0.12` — заново выполнить полный CI выбранного выпуска и только
  после успеха сделать его стабильным с тем же тегом и коммитом. Наличие тестовой `v0.13`
  не меняет выбор. Пропуски номеров между стабильными версиями допустимы.

Стабильный выпуск не создаётся автоматически. Команда «создай релиз» означает продвижение
предварительного выпуска нужной работы; при неоднозначном выборе нужно указать тег.
